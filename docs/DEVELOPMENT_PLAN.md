# 太阳系漫游：Godot 开发方案 V0.1

> 2026-10-08 更新：v0.2.0 已实现探索、资料卡、两项实验、比例比较与本地记录，并产出 Android 调试包。M1 的安卓打包通过，但双端真机验收未完成；M2–M4 的核心功能已推进，视觉、完整手势、无障碍与真机性能仍有待办。详细状态见 `RELEASE_V0.2.0.md`，下文保留原始计划，不代表各阶段均已验收。

## 1. 已确定的产品和技术范围

独立安装的科普 App，同时支持 Android 与 iPadOS / iOS。iPad 和安卓平板为首要设计对象，手机提供紧凑布局。
采用 Godot 4.6.3 stable、带类型标注的 GDScript、Compatibility 渲染器。
首版覆盖太阳、八大行星、地球专题中的月球、天体档案、比例比较、自转与昼夜、公转与一年。
核心内容离线运行，本地保存学习进度和偏好；首版不建设账号、广告、订阅或云端服务。

当前交付属于 M0：工程骨架与日地月工程演示。此前的可点击界面原型是设计参考，尚未全部移植到 Godot。
既有首版功能范围不因骨架只包含三个天体而缩小。

## 2. 体验和布局

一级入口为“出发 / 探索 / 实验室”。行星档案属于探索的下级页面。
主路径：出发 → 进入太阳系 → 选择地球 → 查看档案 → 操作昼夜实验 → 回答问题并获取解释。

- 平板横屏：左侧导航，中间 3D 场景，右侧知识面板；底部为时间与天体选择。
- 平板竖屏：知识面板可收起，保留主要操作。
- 手机：底部导航，知识卡使用半屏／展开两档抽屉，兼容安全区域。
- 单指拖动旋转、双指捏合缩放、点击选择；平移与近景避障在 M2 实现。
- UI 拖动与场景手势互斥。Android 返回先关闭详情／抽屉，再返回上级页面。
- 切换页面、旋转设备、进入后台时保留选择、相机目标和实验状态。
- 正文按实际设备可读性设置，触控目标目标值为至少 44 pt／48 dp 的等效尺寸；不可直接把 Godot 逻辑像素当作物理 dp。

## 3. 代码与场景架构

下列是目标架构，除 README 列出的基础脚本外，其余模块按里程碑逐步实现，不创建没有行为的大量空类。

| 模块 | 责任 | 边界 |
|---|---|---|
| App / Router | 页面导航、返回栈、生命周期 | 不计算轨道 |
| CelestialCatalog | 加载与校验科学参数、资料来源 | 不存渲染缩放值 |
| SimulationClock | 模拟时间、暂停、倍速 | 使用与帧率无关的统一时间 |
| OrbitModel | 根据时间与轨道参数求位置 | 不操作 UI，不用刚体积分维持公转 |
| SolarSystemView | 模型、材质、轨道线、选择反馈 | 把科学坐标映射到展示坐标 |
| ScalePolicy | 探索、大小比较、距离比较 | 每种策略提供可见说明 |
| CameraController | 全景／近景、拖拽、捏合、跟随 | 设置与目标天体相关的距离限制 |
| LessonController | 实验步骤、观察状态、题目反馈 | 教学演示与全局天文时间明确分离 |
| ContentRepository | 资料卡、题库、资源版本 | 内容与界面代码独立 |
| LocalProgress | 设置与进度保存、迁移、错误恢复 | `user://` 写入，带 schema_version |
| AssetLoader | 基础素材加载、失败降级 | 高清资源下载留到后续扩展 |

事件采用 Godot signals：`body_selected`、`time_changed`、`lesson_step_changed`。
优先显式依赖与资源引用，避免所有模块都通过全局单例互相调用。
将主场景拆成可独立运行的探索、详情、实验和 UI 场景；运行时生成重复天体节点。

## 4. 科学数据和显示模型

科学参数至少包含稳定 ID、中文名、分类、平均半径、轨道参数、恒星自转周期和轴倾角。
字段记录数值、单位、定义、来源 URL、校对日期和参考历元（如适用）；异常或缺失值不得默认为零。
以 NASA / JPL 等权威资料为源，逐项审核。素材另设来源与许可清单。

- 探索视图对尺寸和间距进行调整，始终标注“尺寸与距离经调整”。
- 大小比较统一直径比例；距离比较统一距离比例，但定位标记大小不代表直径。
- 教学轨道先采用可解释的开普勒二体近似，不实现 N 体引力系统。
- 真实周期使用统一模拟时间；独立的自转演示注明速度与时间尺度。
- 首版不提供“此刻真实位置”。如果将来增加，另设星历、历元、坐标系和精度验收。
- 自转／昼夜演示说明观察地点和光照关系；公转演示不直接推导四季。
- 月球潮汐锁定、逆行自转、轴倾角等内容须单独校对，避免套用同一旋转动画。

当前 `solar_demo.gd` 的示意数值只用于验证工程，M2 替换，不可作为科学内容沿用。

## 5. 渲染与性能策略

首版使用 Compatibility，基础效果不依赖高端后处理。Mobile 渲染器仅在有明确画面需求且目标真机验证通过后考虑。
不同渲染器不是普通的运行时画质开关，需要分别验证材质、效果与导出。

- 球体网格复用；按距离减少细分，太阳系总览不加载所有天体的最高分辨率纹理。
- 太阳使用自发光／无光照材质，行星使用统一光源方向与简单材质。工程中的 OmniLight 不是完整科学照明模型。
- 阴影、抗锯齿、纹理尺寸分档；不为装饰星空创建大量独立 3D 节点。
- 控制透明叠加与 UI overdraw；文本与图像资源按需要加载。
- 进入后台停止模拟与不必要渲染；恢复时不按后台停留时间突然快进。

性能为目标而非当前测量结果：在选定的最低支持真机上，基础档连续交互至少稳定 30 FPS；较新设备目标 60 FPS。
记录 P95 帧时间、峰值内存、冷启动时间和连续 15 分钟运行的温升／降频趋势。
具体内存、安装包及纹理预算在 M1 真机基线后锁定，不先凭空承诺。

## 7. 设备与测试计划

M1 选定至少一台较低性能 ARM64 安卓设备、一台主流安卓平板、一台 iPad，并补充 iPhone 紧凑布局检查。
具体型号和最低系统版本待设备验证确定；Godot 最低运行要求不等同于本产品承诺支持范围。

| 测试层 | 重点 |
|---|---|
| 纯逻辑 | 时间暂停／倍速、轨道周期与距离、单位换算、显示缩放、进度迁移 |
| 场景测试 | 选择与镜头目标一致，详情返回保留状态，UI 手势不误触场景 |
| 科学验收 | 数据来源、轴倾角、周期关系、光照方向、明暗交界、比例说明 |
| 移动设备 | 多指触控、返回键、安全区、旋转、后台／恢复、存储异常 |
| 性能 | 多天体总览、近景切换、连续运行、内存与温升 |
| 打包 | 全新安装、升级保留进度、无网络冷启动、基础资源完整性 |

只为关键逻辑和已出现的回归风险编写测试，避免测试仅重复场景实现。

## 8. 打包、存储和发布

- Android 使用本地开发 APK 验证，实际发行渠道确定后准备 AAB 或渠道要求的包。
- 苹果端使用 macOS / Xcode，先完成签名真机开发构建，再考虑 TestFlight。
- 占位包名 `org.example.solarsystemexplorer` 在首次正式发布前替换为确定的应用标识。
- Team ID、发布证书与密钥不写入仓库；导出凭据使用本地配置或安全环境变量。
- 本地进度使用版本化 JSON，临时文件写入后原子替换；损坏时备份并恢复默认值。
- 基础内容随应用离线提供；若以后增加资源下载，需要校验、版本清单、空间检查和恢复机制。
- 不在 M0 下载 SDK、修改全局 Xcode 选择、创建发布密钥或发布商店版本。
